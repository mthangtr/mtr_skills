# Brainstorming Brand Names

## Overview

Naming is an interview plus a search loop, not a list dump.

Core principles:
- **A name is a candidate only after it survives a conflict search.** Unchecked names waste the user's rounds.
- **Taste is discovered by reacting to real brands, not described in the abstract.** Calibrate early.

Respond in the user's language. Keep technical terms (SaaS, B2B, trademark) in English when the user does.

## When NOT to Use

- Legal clearance. Refer the user to an IP attorney or trademark agent.
- Naming code (variables, repos).
- The user has already picked a name and only wants a logo or tagline.

## Process

Run one round per turn. Each round has at most 3 questions. Use tappable-option tools when available.

| Phase | Goal | Output |
|---|---|---|
| 1. Discovery | Market (local / regional / global), customer (B2B / B2C), model (product / service / multi-product) | Constraint list (frameworks.md, Appendix A) |
| 2. Strategy | Brand architecture, archetype, core value (Why) | Positioning draft and 3–4 meaning territories |
| 3. **Taste calibration** | 3 groups × 4 famous brands; user picks what they like by sound alone | Decoded pattern: syllables, endings, origin, rejects |
| 4. Generate | 4–6 names per batch, each with root story, pronunciation, Endorsed test ("Product by X") | Batch |
| 5. Check | Search the top 2–3 names before recommending any | Risk label per name |
| 6. Iterate | Map feedback with the diagnostic table below | Next batch |
| 7. Shortlist test | 2 names in a visual mockup: wordmark, app icon, "by X", email signature, domain | Phone, recall and gut tests |
| 8. Handoff | Domain and social handles, trademark search, filing order | Checklist |

Details for each framework are in [references/frameworks.md](references/frameworks.md). The search protocol and risk rubric are in [references/conflict-check.md](references/conflict-check.md).

**Entry points:**
- **User already has a name and wants it confirmed:** start at Phase 5 for that name, then Phase 8. Never confirm registrability; report search findings and the risk label.
- **User has a hard deadline** (meeting, partner reply): this overrides "stop generating" in the diagnostic table. One batch of 3–6 names, search the top 2–3, recommend one checked name framed as a "working name pending trademark search", and put the Phase 3 calibration in the same turn as a closing question.

**Phase 3 is the most important.** If you skip it, vague feedback ("not right", "too soft") keeps returning. For the brand set to show and how to decode the picks, see references/frameworks.md (Appendix A and B).

## Rules for Generating

- **Every name shows its roots.** For example, Orvex = Orbit + Vertex. If you can't explain each part, drop the name.
- **Fix a taken name with a new root combination, never with a tacked-on suffix.** Users read "Zimpl → Zimplo" as patched and safe.
- **Reject one-letter twists of common words** (Zolar from "solar") and **forms that look misspelled** (Ordekt). They are usually taken, and the association locks to the original word.
- **Default to 2 syllables, 3 at most.** Long names (Antikythera, Laniakea) get rejected even when the story is strong.
- **Mark each name "checked" or "unchecked"** in every batch. Recommend only checked names. "Checked" means at least one global company search plus one search per priority country (for a broad region like Southeast Asia, pick the 2–3 countries the user named or will enter first); if no trademark database was searched, say so next to the name.
- **Example names in this skill and its references are illustrations, not candidates.** Never propose them (Orvex, Kaelex, Celar, Sentar, Ordifex, Levifex, Tornus, Forfex, etc.).
- **Read each name with the local spelling rules.** Vietnamese readers turn English syllables into Vietnamese ones (Zenarc → "ác", evil). Drop names whose local reading is a bad word.

## Feedback Diagnostic

| User says | Likely cause | Next move |
|---|---|---|
| "Too soft / gentle" | Soft consonants (l, m, n) and open vowel endings (-a, -ia, -o) | Use plosives (k, t, d), closed endings (-ex, -ar, -on), 2 syllables |
| "Feels patched / too safe" | Variants built to dodge conflicts | Combine new roots with real morphology (Latin -fex, two-root blends) |
| "Looks misspelled" | Odd consonant clusters | Spell phonetically; one obvious reading |
| "I like X because it sounds like [famous brand]" | Familiarity bias | Keep the sound structure, drop the resemblance (avoids the Copycat flaw) |
| "Not outstanding" | Meaning too modest or earthly | Raise the scale: cosmic, mythic, future technology |
| "Too long" | 3+ syllables or compounds | Cap at 2 syllables |
| No enthusiasm after 3 rounds | Taste not decoded | Stop generating; run or redo Phase 3 |
| Wants short + real word + grand + globally unused | These criteria cannot all be met | Show the four criteria; ask which one to relax |

## Practical Uniqueness Bar

Global uniqueness is unrealistic. The brands users admire did not have it either: "Linear" and "Stripe" are common words.

The practical bar for a candidate:
- No registered trademark in the user's classes (software: Nice 9 and 42) in the target markets.
- No strong same-industry company in those markets.
- A usable domain variant.

Short real Latin or Greek words and "grand" words are the most crowded. Two-root coinages are the most open. See references/conflict-check.md for the saturation map.

## Common Mistakes

| Mistake | Fix |
|---|---|
| Recommending names before searching | Search the top picks first; label the rest "unchecked" |
| 20-name lists | 4–6 names, each with a story |
| Asking about taste abstractly ("soft or sharp?") | Use brand benchmarks (Phase 3) |
| Checking only globally | Also search the target market. A same-name SaaS in the expansion region is a hard stop. |
| Endless batches | After about 3 batches of strong candidates, move to the shortlist test |
| Presenting legal conclusions | Give search findings and filing steps; recommend a trademark agent |
